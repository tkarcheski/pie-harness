# Operated recovery drill

From a standalone checkout on Node.js 22.13 or newer, run `node apps/recovery/drill.mjs 30` for a thirty-minute wall-clock drill. The command accepts durations up to sixty minutes and exits unsuccessfully if a target is missed. Run `node --test tests/recovery-drill.test.mjs` for a short CI smoke test.

1. A worker subprocess persists an artifact checkpoint. The operator terminates the worker during its lease. A second enrolled node recovers the checkpoint and completes the task. The old worker's attempt to complete it must fail. Children also terminate on IPC disconnect or when their fifteen-second watchdog expires.
2. Studio queues a synthetic product draft. The drill places a consistent SQLite snapshot, its matching enrollment key, and a SHA-256 manifest in a separate backup directory. It checks SQLite integrity and verifies that the active enrollment matches the key before writing the manifest.
3. The drill removes its disposable source directory, including the original key, database, and maintenance snapshot. It opens a fresh Studio from the bundle alone. The restored worker must complete the previously queued product task and produce the expected draft in review. The journal records the task ID and draft digest.
4. The restored queue runs until the requested duration elapses. The journal records periodic progress and reconciles the exact number of completed tasks. Final JSON includes the journal path, bundle path, timings, and database integrity result.

Each drill keeps its artifacts in a fresh OS temporary directory. POSIX directories and bundled files use modes `0700` and `0600`. On Windows the drill protects the temporary root, backup and restored directory with an inheritable access rule for the current account. Treat the backup and restored directories as credentials. Share a redacted report when reporting the result. A missing manifest, altered snapshot, mismatched or revoked enrollment, or occupied restore destination stops recovery. Use a fresh restore directory when retrying.

The exercise uses a 1.2-second lease with a three-second heartbeat window. Its lab targets are fifteen seconds from worker loss to replacement completion and fifteen seconds to create the backup and produce a draft on the restored Studio. The fixture model runs locally. Both directories are on the same host. An operating deployment's recovery point depends on the age of its most recent usable off-machine backup. Measure its restore time against the deployment's own data size and storage. [Studio maintenance](local-operations.md)
