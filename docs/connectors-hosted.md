# Hosted text turns

The `HostedResponses` adapter uses an operator-authorized OpenAI API project key with Responses background execution. Select a deployed model that supports background mode. The provider stores the response for retrieval. Review the provider's retention terms before submitting sensitive inputs. Account subscriptions for coding tools use their own supported native sign-in; this adapter requires API project access and billing. [Provider background execution and cancellation](https://developers.openai.com/api/docs/guides/background)

Register an `openai-responses` account with the local account registry, an opaque secret reference and scopes `hosted.turn`, `hosted.observe` and `hosted.cancel`. Supply a trusted secret resolver when constructing the adapter. Give the submitting actor a time-limited standing grant or exact approval and configure the business budget. The serialized proposal specifies model, prompt and maximum output tokens. Hash `serializeTurn(spec)` for the owner approval. Its object is the model ID and its amount is the operator's approved charge ceiling. Reconcile actual provider billing separately.

1. Claim a local task with an original deadline within one hour. Submit using `runtime.submit(owner, task, worker, proposal, spec)`. The engine reserves the effect budget before network dispatch. The remote request contains a bounded text input and an empty tools list.
2. Inspect the hosted status via `runtime.supervise(owner, task)` from a trusted supervisor on its regular tick. The submission task records provider acceptance. Downstream consumers use the hosted status for readiness. A running supervisor requests remote cancellation at the deadline. If the supervisor was offline, reconcile remote status at restart.
3. For provider event processing, call `runtime.refresh(owner, task, {eventId, responseId})`. Integrators authenticate incoming webhook traffic at their application boundary. An event is a retrieval hint. The adapter retrieves the authoritative response and matches its submission metadata before accepting the update. Repeated events return the recorded state. An ambiguous create response remains pending until a verified response ID is available or the operator establishes recipient absence.
4. Use `runtime.cancel(owner, task)` to request an early stop and `runtime.result(owner, task)` to retrieve a verified completed text response. Select a private artifact destination for the returned bytes. State keeps the output digest and opaque provider and task IDs. Credentials, raw prompts, answer text and provider error bodies stay outside audit state.
5. Pause or revoke the account to stop further connector calls. Where possible, cancel pending remote jobs before revoking credentials. A revoked key can leave a provider-owned job requiring intervention through the provider account.

The adapter checks the active credential revision after reading each provider response and before accepting a receipt or releasing answer text. A response that spans credential rotation or containment requires a fresh authorized read.

The standalone tests run against an in-memory recipient and exercise approval, lost acknowledgments, cancellation, revocation, output verification and duplicate callbacks without a hosted account.
